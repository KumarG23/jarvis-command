# Jarvis Command v0.1 Vertical Slice Implementation Plan

> **For Hermes:** Use subagent-driven-development practices to implement this plan task-by-task. GPT-5.6 Sol at maximum available reasoning effort owns every implementation and review decision.

**Goal:** Replace the static bootstrap with a secure, responsive Jarvis Command shell that verifies Cloudflare identity at the origin and displays live, sanitized Hermes readiness, capabilities, and recent sessions through a narrow BFF.

**Architecture:** Use an npm-workspaces TypeScript monorepo with a React/Vite PWA, a Fastify BFF, and shared Zod contracts. The browser talks only to same-origin BFF endpoints. The BFF validates Cloudflare Access JWTs and communicates with Hermes’s official API Server through a dedicated loopback-to-loopback SSH tunnel; it never exposes or forwards Hermes credentials to the client.

**Tech Stack:** Node.js 22, npm workspaces, TypeScript 7, React 19, Vite 8, Fastify 5, Zod 4, jose 6, Vitest 5, Testing Library, Playwright 1.62, Docker/Compose, Cloudflare Access and Tunnel.

**Design direction:** An original Jarvis identity built from Linear-like information precision and Warp-like command blocks: near-black native canvas, restrained surfaces, warm readable text, emerald/cyan operational signals, concise typography, subtle borders, no glassmorphism sludge, no fake sci-fi HUD clutter.

## Task 10: Establish the restricted Hermes transport

**Objective:** Connect VM 113 to the loopback-only Hermes API without exposing Hermes on the LAN.

**Operations:**
1. Generate a dedicated Ed25519 forwarding key on VM 113.
2. Add the public key to Hermes with `restrict,port-forwarding,permitopen="127.0.0.1:8642"` and no shell/agent/X11/PTY capabilities.
3. Stage Hermes API Server config on loopback port `8642` with a random bearer credential and bounded concurrent runs.
4. Because Jarvis cannot restart its own running gateway safely, ask Neal to issue `/restart` only after config and rollback evidence are prepared.
5. Install an enabled systemd SSH-forward unit on VM 113 mapping local `127.0.0.1:18642` to Hermes `127.0.0.1:8642` with strict host-key checking, keepalives, exit-on-forward-failure, and restart backoff.
6. Transfer the bearer credential directly between hosts into a root-owned production env file; never print or send it through chat.
7. Verify unauthorized Hermes calls return 401, authorized calls return expected contracts, and neither listener is LAN-reachable.

**Commit:** Infrastructure templates/runbook only; never commit keys or credentials.
