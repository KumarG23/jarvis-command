# Jarvis Command v0.2 — Live Room Implementation Plan

> Status: implementation approved 2026-09-04. This plan executes the canonical Obsidian roadmap; it does not redefine it.

## Goal

Ship one secure Jarvis Command-owned Hermes session that Neal can open from desktop or the installed Pixel TWA, use for a real streamed turn, supervise through typed events, approve once or deny a gated action, steer or stop, and recover honestly across stream loss, process restart, and VM reboot.

## Non-negotiable boundaries

- Keep `apps/read-proxy` and its credential/allowlist unchanged.
- Add a distinct loopback-only `apps/command-proxy` with its own BFF credential. Only it receives the unrestricted Hermes API key on the Hermes host.
- The BFF exposes purpose-built endpoints only. It never exposes a generic path, upstream credential, Access assertion, or reusable bearer token to the browser.
- Only sessions with a generated `jc_` ID and allowed Hermes source are writable. Gateway-owned sessions are read-only; `Continue in Command` creates a `jc_` fork.
- Browser mutations require a verified Access identity, exact configured origin, JSON content type, a non-simple custom request header, bounded input, per-actor rate limiting, and append-only audit admission.
- v0.2 approval choices are exactly `once` and `deny`.
- Every run uses Hermes's durable `Idempotency-Key`. The browser retains only opaque request/run/session identifiers—never credentials or transcript payloads.
- One UI writer per session is a UX guard, not the concurrency authority; Hermes remains authoritative.
- No application-image deployment precedes a clean tree, frozen commit, independent review of that exact commit, and all local gates.

## Architecture

```text
Pixel TWA / desktop browser
  -> Cloudflare Access + Tunnel
  -> VM 113 Fastify BFF :3000
       read snapshot -> 127.0.0.1:18642 -> read proxy :8643
       live commands -> 127.0.0.1:18643 -> command proxy :8647
       audit/registry -> /var/lib/jarvis-command/audit/events.jsonl
  -> Hermes API :8642 (loopback only)
```

The audit log is a hash-chained append-only JSONL ledger. It stores actor fingerprints, opaque client/public/upstream run IDs, session IDs, action/outcome/status, sequence, timestamps, and hashes—but no assertion, credential, prompt, steer text, raw command, or model output. Startup validates the complete chain and reconstructs public-run mappings; mutation fails closed if the ledger cannot be validated or appended.

## Public BFF contract

- `GET /api/sessions/:sessionId/messages?limit=&offset=` — paginated projected history.
- `POST /api/live/sessions` — create a Command-owned session.
- `POST /api/live/sessions/:sessionId/continue` — fork any readable session into Command ownership.
- `POST /api/live/runs` — submit `{ sessionId, input, clientRequestId }`; return opaque `publicRunId` and replay state.
- `GET /api/live/runs/:publicRunId` — authoritative projected status.
- `GET /api/live/runs/:publicRunId/events` — typed SSE stream; status polling is the recovery authority after stream loss.
- `POST /api/live/runs/:publicRunId/approval` — exact `{ requestId, choice: "once" | "deny" }`.
- `POST /api/live/runs/:publicRunId/steer` — bounded `{ input }`; UI labels acceptance as queued.
- `POST /api/live/runs/:publicRunId/stop` — request cooperative stop; UI keeps `stopping` nonterminal.

#### Local BFF checkpoint constraints

The installed Hermes `/api/sessions/{id}/fork` endpoint marks its source session as `branched` before copying history. The current public API therefore cannot satisfy non-mutating **Continue in Command** for gateway-owned sessions. The command proxy rejects external sources before invoking fork; only verified Command-owned sources can be branched. Bootstrap explicitly reports `externalContinue: false`. The original external-continuation acceptance criterion remains blocked, not silently redefined as complete.

Unknown run-admission recovery is limited to 23 hours from the durable request receipt, inside the verified minimum 24-hour Hermes idempotency retention. Command readiness requires supported, durable idempotency with at least that retention; process-memory fallback disables admission. This does not promise indefinite upstream status retention.

This is an uncommitted local BFF checkpoint, not a v0.2 release. Live Room UI and deployment integration remain separate steps. Preserve the existing read-proxy implementation and default disabled command mode. Deployment must preflight the proposed command-proxy listener against existing Hermes-host services before choosing its actual port.

Approval projection is intentionally conservative: recognized credential assignments/Bearer values are redacted only when their values are simple unquoted token characters. Quoted values, escapes, shell operators/substitutions, or ambiguous spans in the command, description, or tool label cause the entire card to fail closed; the operator must use another trusted approval surface or stop the run. Commands that exceed the display cap before or after redaction are rejected, never truncated. This is not a shell parser or a guarantee of arbitrary free-text secret detection.

History binds the exact requested session, every message, limit, offset, returned count, and explicit `oldest` order before projection. The installed Hermes message API has no total/has-more field; `hasMore` means a full page may have a successor, not a proven remaining record. A final page exactly at the limit therefore permits one additional empty-page fetch. Oversized message identifiers are rejected rather than sliced.

Identity fields are never display text: approval IDs use one shared exact printable-ASCII/no-whitespace policy (256 characters); message/tool/subagent identifiers use the same policy capped at 160. Numeric upstream message IDs must be nonnegative safe integers before decimal projection. Session IDs use the shared session syntax and 160-character cap. Status, history, bootstrap session lists, and SSE reject malformed/oversized identities instead of slicing or trimming them; missing subagent IDs refuse the event rather than inventing `unknown` (the supported `child_session_id` alias remains). These rules apply at the proxy, HTTP client, and public contract boundaries. Human-readable previews and labels retain their separate display policies.

### Local UI checkpoint (not a release)

The local Live Room implementation now covers selection/history/pagination, Command session creation, composer and typed streams, bounded recovery, exact approval once/deny, queued steer, confirmed cooperative stop, room-bound in-memory drafts, and opaque-ID-only reload recovery. Restored identifiers are untrusted hints: consequential controls remain disabled until an authoritative status response binds the exact run and session. Fresh admission acknowledgements establish that binding for newly submitted turns.

Reload during uncertain admission before a public run ID exists cannot recover by client request ID through the current BFF API. It deliberately remains locked for trusted operator reconciliation; losing the prompt/issuance time must not trigger a new UUID or replacement admission. External `Continue in Command` remains disabled because the installed upstream fork operation mutates its source, as documented above. History/output overlap suppression requires a complete pre-send baseline plus a new assistant message ID; equal historical text alone does not prove run identity.

`npx playwright test -c e2e/integration.config.ts` builds fresh assets and exercises desktop/phone PWA clients under an active service worker through actual JWT-verifying BFF composition, real HTTP clients, both proxies, and a durable audit ledger. Only signing identities and the loopback Hermes upstream are synthetic. It covers typed streaming/terminal output, denied mutations, both approval choices, queued steer, ID-only reload, BFF-only restart on the same origin/audit, confirmed stop and terminal pending-steer handoff. It is not live Cloudflare/OTP/MFA, real Hermes, VM reboot, or production cutover evidence. Backend source is transformed by the test runner; emitted-entrypoint/container verification remains a separate gate.

## Rollback rule

If any post-cutover check fails, restore the previously approved app image, environment, service state, bridge policy, and command-proxy state from the captured transaction snapshot. A degraded read-only v0.1 is preferable to a write-capable half-release. The goblin does not get a production shell because the progress bar reached 97%.
