## Requested choices and availability

The existing prompt model/effort choice stays separate and browser-local. Opening its picker reads the exact current thread default and, within a project, that exact project's default. Nothing automatically migrates or saves the browser choice. Saving or clearing is an explicit preference action; it creates no session, message or run.

The controls use existing strict `RoutingDefaultTarget`, `RoutingDefaultSet` and `RoutingDefaultResponse` schemas, same-origin credentials, `no-store`, `redirect:error` and the existing bounded JSON reader (10 seconds, 2 MiB). An invalid target makes no request. Every response must match the requested target; a mutation must also match the expected next revision and requested selection. The supported response has no actor or request-UUID echo: authorization remains server-owned, while unknown response fields are rejected. Each deliberate mutation supplies a fresh validated UUID and the read revision.

Only explicit `writesAvailable:true` on every relevant readback enables preference changes or opt-in to new defaults-mode sends. Missing/false/loading/error is unavailable, retaining requested readback and working legacy sends. The client never probes a mutation for capability and introduces no activation flag. A fresh read before a new opted-in send checks availability again; the backend remains authoritative for current eligibility, membership and precedence.

A conflict, malformed response, transport failure or timeout does not replay a mutation. It may already have landed. The controls preserve readback/draft, unlock explicit refresh, then require another deliberate change with the refreshed revision. Context changes/unmount abort pending work and ignore late success or denial. Transport cancellation cannot guarantee server rollback. Opting out during a refresh stays opted out; stale completion cannot restore it or change another pane's selection or focus.

## Send and recovery boundary

“Use saved defaults for the next message” is an explicit, context-local opt-in. It adds `routing:{mode:'defaults',projectId:<exact current project id or null>}` and leaves any prompt `inference` override separate. The server resolves prompt → thread → project → Command; the browser does not resolve or silently inherit a route. Unavailable defaults-mode sends retain the draft without a legacy fallback. The user can explicitly opt out to use the unchanged legacy path.

The composer passes routing through both main and retained-thread send adapters. `useLiveTurn` rejects a mismatched project envelope before allocating an identity. It copies and freezes the submitted inference, routing and image references with the request UUID. Manual same-intent retry uses that committed envelope, including after changed choices/defaults and 409/503 responses. Preference reads or capability changes do not reconstruct an uncertain send. Existing reload recovery persists only request/run identity and project scope, performs read-only lookup, and never automatically reposts; old queued/legacy envelopes are not converted to defaults mode.
