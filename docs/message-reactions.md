## Phase 1 UI source (#98 follow-through)

The BFF advertises that entry only for its existing enabled reaction flag and a ready composed live service; an upstream advertisement cannot enable it. Absence leaves a visible unavailable notice with no per-message probes. External/read-only and archived-project views remain unavailable. Runtime configuration is unchanged.

The compact seven-choice picker appears only on eligible canonical user/assistant history rows. It keeps the loaded 50-row page's known offset for the backend's one-page verification. Transient turns, tool/display/setup rows and omitted echoes have no controls. Reads are lazy on explicit open/refresh, globally limited to one reaction request at a time; the shell retains at most 64 target states. Settled entries may be evicted; unresolved intents are retained. No timer, history scan or per-render fetching is added.

Each explicit choice sends `add` or `remove` with a new UUID. Known success is followed by one authoritative read before another choice is enabled. An unconfirmed response retains the exact original request, locks other choices, and requires an explicit saved-state check before manual retry with that same UUID. A replay receipt never replaces current state without readback. Pending state survives history-component remounts and session/pane switches within the authenticated shell. A full shell reload starts without cached actor state and requires a fresh authoritative read; no reaction is automatically replayed. No transcripts, actor identifiers or reaction cache are written to browser storage.

Picker actions have text labels and pressed state; Escape/Close returns focus to the trigger. Choices wrap in a bounded scrollable panel inside history, with 44px actions above the composer.
